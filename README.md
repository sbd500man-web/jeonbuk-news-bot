**전북 뉴스 → 텔레그램 알림 프로그램 / 처음 사용하는 분을 위한 설치 안내**

중요 기사 알림 추가: 기존 지역 조건을 통과한 새 기사의 제목·검색 요약에서 `속보`, `단독`, `특종`을 판별합니다. 중요 기사는 이모지 강조 알림 1건을 먼저 보내고 일반 알림도 보냅니다. 여러 표시가 함께 있어도 강조 메시지는 기사당 1건입니다. `단독주택`, `속보치` 등 붙어 있는 다른 단어와 `단독 후보`, `단독 선두`, `단독 인터뷰`, `특종 보험` 등의 일반 표현을 제외합니다. 명시적인 `[단독]` 표시는 인정합니다. 의미를 이해하는 분류기가 아닌 규칙 기반 판별입니다. 이미 처리한 기사는 다시 알리지 않으며, 기존 `data/state.json`을 유지해야 합니다. 한 번에 최대 30개 기사를 처리하므로 메시지는 최대 60건입니다.

2026-11-08 수정: 네이버 검색 API 신규 신청이 NAVER API HUB로 이전된 것을 반영해 신청 안내와 코드의 접속 주소·인증 방식을 수정했습니다. 이전 ZIP 대신 이 수정본을 사용하세요. GitHub Secrets 이름은 그대로이며, 값은 API HUB에서 새로 발급받은 Client ID/Secret을 넣습니다.

내 컴퓨터에 Python을 설치할 필요가 없습니다. 파일을 GitHub에 올리면 GitHub의 컴퓨터가 정해진 시간마다 실행합니다. 설치 후 내 컴퓨터를 꺼도 작동합니다. 다만 아래에서 본인의 계정으로 발급받는 비밀값 4개를 등록해야 실제 수신이 시작됩니다.

**1. 어떤 기사를 보내나요?**

- 검색어: `전북`, `전북자치도`, `전라북도`, `전북 경찰`, `전북 소방`.
- 다섯 검색어 중 하나 이상이 검색 결과의 **제목 또는 요약**에 있는 기사를 보냅니다. `전북경찰`처럼 붙여 쓴 표현도 확인합니다. `전북`이 포함되므로 `전북특별자치도`도 포함됩니다.
- 네이버는 공식 뉴스 검색 API, 다음은 실제 뉴스 검색 페이지를 읽습니다. 구글 검색으로 대체하지 않습니다.
- 본문 전체를 내려받아 검사하지는 않습니다. 본문에만 검색어가 있고 제목·검색 요약에는 없으면 놓칠 수 있습니다. 포털 검색에 잡힌 언론사 원문 링크도 포함됩니다.
- 24시간 동안 매시 **00·10·20·30·40·50분**에 실행을 요청합니다. GitHub 실행 대기와 수집 시간 때문에 도착은 늦어질 수 있습니다.
- 처음에는 **포털별 최근 24시간 이내 최신 기사 최대 5건**을 보냅니다. 두 포털 합쳐 최대 10건이며, 중복 링크가 있으면 더 적습니다. 기존 나머지 기사는 기록만 하고 보내지 않습니다.
- 두 번째부터는 새로 발견한 기사를 보냅니다. 한 번에 최대 30건을 보내고, 초과한 기사는 대기열에 보관해 다음 실행에서 보냅니다.
- 같은 기사가 여러 검색어에 걸려도 링크 기준으로 중복을 막습니다. 네이버는 언론사 원문 링크를 우선 사용해 구분합니다. **네이버·다음의 주소가 서로 다른 동일 기사까지 완전히 합치지는 않습니다.** 같은 사건의 다른 기사도 각각 보냅니다.
- 첫 실행에 `전북 뉴스 봇이 시작됐습니다`라는 안내가 옵니다. 이후 두 포털 검색이 정상 완료되고, 보낸 기사·대기 기사·최근 10분 내 기사가 모두 없으면 `관련 키워드로 최근 10분간 올라온 기사가 없네요 ㅠㅠ, 그냥 웹서핑이나 하시죠`를 보냅니다. 같은 10분 구간에는 한 번만 보냅니다. 검색 오류나 조회 상한 경고가 있으면 잘못된 부재 안내를 보내지 않습니다.
- 최근 10분은 실제 수집 시작 시각 기준이며 포털의 검색 결과 시각으로 판별합니다. 늦게 검색에 반영된 기사를 놓치지 않도록 기존 최근 24시간 조회와 중복 방지를 유지합니다. 이미 보낸 최근 기사가 있으면 반복 실행 시 기사 없음 안내도 보내지 않습니다.

수신 메시지 예시입니다. 아래는 실제 기사 인용이 아닌 형식 예시입니다.

```text
[전북 뉴스 · 네이버]
전북 소방, 현장 안전 점검 실시

검색 결과에 표시된 기사 요약...

검색 결과 표시 시각: 11/06 09:30 (한국시간)
키워드: 전북, 전북 소방
기사 링크
```

**2. 텔레그램 봇 만들기 — 비밀값 ① 받기**

1. 휴대전화나 PC에서 텔레그램에 로그인합니다.
2. 공식 [BotFather](https://t.me/BotFather)를 엽니다. 사용자 이름이 정확히 `@BotFather`인지 확인합니다.
3. `시작 / Start`를 누르고 `/newbot`을 보냅니다.
4. 봇 이름을 입력합니다. 예: `전북 뉴스 알림`.
5. 봇의 사용자 이름을 영문으로 입력합니다. 끝은 `bot`이어야 합니다. 예: `my_jeonbuk_reporter_123_bot`. 이미 사용 중이면 숫자를 바꿉니다.
6. BotFather가 보내주는 `123456789:AA...` 형태의 긴 문자열이 **봇 토큰**입니다. 잠시 메모해 둡니다. 나중에 `TELEGRAM_BOT_TOKEN`이라는 이름으로 등록합니다.
7. BotFather가 알려준 새 봇의 링크를 열어 **Start를 누르고 `/start` 또는 `안녕`을 보냅니다.** 새로 만든 봇에 직접 보내야 합니다. 봇은 이때 답을 하지 않아도 정상입니다.

토큰은 봇의 비밀번호입니다. 코드 파일, GitHub 게시글, 공개 저장소, 이 채팅에 붙여 넣지 마세요. 아래 GitHub Secrets에만 저장합니다. 노출했다면 BotFather에서 해당 봇의 토큰을 재발급받으세요.

공식 안내: [Telegram 봇 생성](https://core.telegram.org/bots/tutorial).

**3. 내 채팅 번호 찾기 — 비밀값 ② 받기**

1. 개인 PC의 웹브라우저 주소창에 아래 주소를 넣되, `여기에_봇_토큰` 부분을 2단계에서 받은 실제 토큰으로 바꿉니다. `<`나 `>`는 넣지 않습니다.

   ```text
   https://api.telegram.org/bot여기에_봇_토큰/getUpdates
   ```

2. 화면에 글자가 많이 나와도 정상입니다. `Ctrl+F`로 `"chat"`을 찾습니다.
3. 그 바로 뒤에 있는 `"id"`의 숫자를 메모합니다. 예를 들어 아래에서는 `123456789`입니다. `update_id`나 봇 자신의 ID를 복사하지 마세요.

   ```json
   "chat": {"id": 123456789, "first_name": "내 이름", "type": "private"}
   ```

4. 이 숫자가 나중에 등록할 `TELEGRAM_CHAT_ID`입니다. 본인의 이름이 있는 `private` 채팅을 선택합니다.

`"result": []`만 보이면 새 봇에게 `/start`를 다시 보내고 브라우저를 새로고침하세요. `404`는 주소·토큰 오타, `401`은 토큰 오류일 가능성이 큽니다. 다른 서비스에서 이미 사용한 봇에 `409`가 나오면 이 프로그램 전용 새 봇을 만드는 편이 쉽습니다. 조회한 주소에는 비밀번호인 토큰이 들어 있으므로 주소나 화면을 공유하지 말고, 확인 후 해당 방문 기록도 지워 주세요.

공식 안내: [Telegram getUpdates](https://core.telegram.org/bots/api#getupdates).

**4. 네이버 검색 이용 신청 — 비밀값 ③·④ 받기**

1. [네이버 클라우드 플랫폼](https://www.ncloud.com)에 가입·로그인한 뒤 [콘솔](https://console.ncloud.com)을 엽니다. 기존 네이버 개발자센터의 신청 화면은 사용하지 않습니다.
2. 콘솔에서 `Menu → All Services → Application Services → NAVER API HUB`로 이동합니다. 리전 선택이 필요하면 한국 리전을 사용합니다.
3. 처음이면 `Subscription → 서비스 이용 신청`에서 약관을 확인하고 동의합니다.
4. `Application → Application 등록`을 누릅니다.
5. API 선택 화면에서 **`NAVER 검색` 카테고리의 `뉴스`만 선택**하고 `다음`을 누릅니다.
6. Application 이름에는 `jeonbuk-news-bot`을 입력하고 `완료`를 누릅니다. 이름은 최대 20자의 영문·숫자·하이픈으로 작성합니다.
7. 등록된 Application의 `인증 정보`에서 `Client ID`와 `Client Secret`을 각각 복사합니다. 콘솔에 표시되는 헤더 이름은 각각 `X-NCP-APIGW-API-KEY-ID`, `X-NCP-APIGW-API-KEY`입니다.
8. GitHub에는 아래 7단계의 기존 이름 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`으로 저장합니다. 코드가 새 인증 방식으로 전달합니다.

다음 수집을 위한 카카오 API 키는 필요하지 않습니다. NAVER API HUB는 2026-11-08 확인한 공식 안내상 한시적 무료이며, 유료 전환 시 사전 공지 예정입니다. 신청 화면의 요금과 이용 한도를 확인하세요. 이 프로그램은 재시도·수동 실행을 제외하면 10분 간격 기준 최대 약 7,200회/일이며 보통은 더 적게 호출합니다. 같은 키를 다른 프로그램에서도 사용하면 호출량이 합산됩니다. 클라우드 서버를 별도로 만들 필요는 없습니다. 프로그램 실행은 GitHub Actions가 담당합니다.

공식 안내: [이관 공지](https://developers.naver.com/notice/article/32530), [API HUB 신청·등록](https://guide.ncloud-docs.com/docs/apihub-application), [뉴스 검색 API](https://api.ncloud-docs.com/docs/naver-api-hub-search-news), [무료 제공 안내](https://guide.ncloud-docs.com/docs/apihub-overview).

**5. GitHub에 프로그램 보관함 만들기**

GitHub의 `Repository`는 프로그램 파일을 보관하는 폴더라고 생각하시면 됩니다.

1. [GitHub](https://github.com)에 가입하고 로그인합니다.
2. [새 저장소 만들기](https://github.com/new)를 엽니다.
3. Repository name에 `jeonbuk-news-bot`을 입력합니다.
4. 공개해도 괜찮다면 `Public`을 선택합니다. 이 설정에서는 프로그램과 기사 처리 기록을 다른 사람도 볼 수 있습니다. 토큰은 나중에 Secrets에 넣으므로 파일에 들어가지 않습니다.
5. `Add a README file`을 켜고 `Create repository`를 누릅니다.

공개 저장소의 일반 GitHub 제공 실행기는 무료입니다. `Private`은 계정의 포함 사용량을 소모하고 초과 시 과금되거나 실행이 제한될 수 있습니다. 10분 간격이면 하루 144회, 30일에 4,320회를 실행하므로 비공개 저장소를 선택할 때는 계정의 사용량·예산 화면을 확인하세요. 코드의 실행기는 일반 `ubuntu-latest`입니다. [GitHub 공식 요금 설명](https://docs.github.com/en/billing/concepts/product-billing/github-actions).

**6. 파일 올리기**

1. 받은 `jeonbuk-news-bot.zip`을 마우스 오른쪽 버튼으로 눌러 압축을 풉니다.
2. 압축을 푼 `jeonbuk-news-bot` 폴더를 엽니다.
3. GitHub 저장소의 `Code` 화면에서 `Add file → Upload files`를 누릅니다.
4. 다음 네 파일을 선택해서 올립니다.
   - `news_bot.py` — 뉴스 수집·전송 프로그램
   - `requirements.txt` — 필요한 라이브러리 목록
   - `test_news_bot.py` — 전송 없이 동작을 확인하는 테스트
   - `README.md` — 이 설치 안내
5. 화면 아래 `Commit changes`를 눌러 저장합니다. 같은 이름의 README가 이미 있다면 받은 안내 파일로 교체하면 됩니다.

**폴더 전체를 한 겹 더 올리지 마세요.** GitHub 첫 화면에서 `news_bot.py`와 `requirements.txt`가 바로 보여야 합니다. ZIP 파일 자체를 올리는 것도 아닙니다.

**7. 비밀값 4개 등록하기**

저장소에서 다음 메뉴로 이동합니다.

`Settings → Secrets and variables → Actions → Secrets → New repository secret`

아래 표의 왼쪽 값을 `Name`에, 오른쪽에서 준비한 실제 값을 `Secret`에 넣고 `Add secret`을 누릅니다. **네 번 반복합니다.** Name은 대소문자와 밑줄까지 그대로 입력합니다.

| Name에 입력할 이름 | Secret에 입력할 내용 |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | BotFather가 준 긴 봇 토큰 |
| `TELEGRAM_CHAT_ID` | 본인의 개인 채팅 숫자 ID |
| `NAVER_CLIENT_ID` | NAVER API HUB에서 발급한 Client ID |
| `NAVER_CLIENT_SECRET` | NAVER API HUB에서 발급한 Client Secret |

값에 따옴표를 붙이지 마세요. `Variables` 탭이나 `Environment secrets`가 아닌 **Repository secrets**에 등록합니다. 저장 후 값을 다시 볼 수 없고 이름만 보이는 것은 정상입니다. 수정은 연필 버튼을 누르면 됩니다.

공식 안내: [GitHub Secrets 등록](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets).

**8. 자동 실행 파일 만들기**

1. 압축을 푼 폴더 안에서 `.github → workflows → news.yml`을 메모장으로 엽니다. 파일이 안 보이면 파일 탐색기의 `보기 → 표시 → 숨긴 항목`을 켭니다.
2. 메모장에서 `Ctrl+A`, `Ctrl+C`로 파일 내용을 전부 복사합니다.
3. GitHub 저장소의 `Code → Add file → Create new file`을 누릅니다.
4. 파일 이름 칸에 다음을 **정확히** 입력합니다. `/`를 입력하면 GitHub가 폴더를 자동으로 만듭니다.

   ```text
   .github/workflows/news.yml
   ```

5. 큰 편집 칸에 복사한 내용을 붙여 넣습니다. 코드 앞뒤에 ``` 같은 표시를 덧붙이지 않습니다.
6. `Commit changes`를 누릅니다. 선택지가 나오면 기본 브랜치 `main`에 바로 저장합니다.

파일명은 `news.yml.txt`가 아니라 `news.yml`이어야 합니다. 이 파일이 기본 브랜치에 있어야 정기 실행됩니다. 압축 폴더 전체를 올려서 이미 같은 경로의 파일이 있다면 새로 만들 필요가 없습니다.

완료 후 GitHub 파일 구조는 다음과 같습니다.

```text
jeonbuk-news-bot
├── news_bot.py
├── requirements.txt
├── test_news_bot.py
├── README.md
└── .github
    └── workflows
        └── news.yml
```

**9. 전송 기록 저장 권한 확인**

코드에는 전송 기록을 저장할 `contents: write` 권한을 지정해 두었습니다. GitHub가 기록 저장을 막는 경우 저장소의 `Settings → Actions → General → Workflow permissions`에서 `Read and write permissions`를 선택하고 `Save`를 누르세요. `Allow GitHub Actions to create and approve pull requests`는 켤 필요가 없습니다.

조직 정책이나 기본 브랜치 보호 규칙이 쓰기를 막으면 이 설정만으로 해결되지 않을 수 있습니다. 개인 계정의 새 저장소로 시작하면 단순합니다. 정상 실행 후 `data/state.json`이 자동으로 생성됩니다. 이것이 이미 처리한 기사와 아직 못 보낸 기사를 기억하는 파일이므로 임의로 삭제하지 마세요.

**10. 내 텔레그램으로 시험 전송**

1. 저장소 상단 `Actions` 탭을 누릅니다. 처음에 실행 허용 화면이 나오면 허용합니다.
2. 왼쪽에서 `Jeonbuk News Bot`을 선택합니다.
3. 오른쪽 `Run workflow`를 누릅니다.
4. Branch가 `main`인지 확인하고 `test_only` 체크박스를 켭니다.
5. 초록색 `Run workflow` 버튼을 누릅니다.
6. 잠시 후 텔레그램에 **`전북 뉴스 봇 연결 테스트 성공!`**이 오면 토큰·채팅 번호가 맞습니다. 테스트 모드는 뉴스 수집과 처리 기록을 변경하지 않습니다.
7. 다시 `Run workflow`를 누르고, 이번에는 **`test_only`를 끈 상태**로 실행합니다. 초기 실행에서는 시작 안내와 기사가 오며, 정상 검색 결과가 비어 있으면 기사 없음 안내가 옵니다.

이후에는 정기 실행됩니다. `test_only`는 그 수동 실행에만 적용되며 정기 실행은 항상 뉴스를 수집합니다. 화면에 노란색 원은 실행 중, 초록색 체크는 성공, 빨간색 X는 실패입니다. 실행 항목을 눌러 `notify → 뉴스 수집과 텔레그램 전송`을 열면 어떤 단계에서 문제가 생겼는지 확인할 수 있습니다.

**11. 문제가 생겼을 때**

| 증상 | 확인할 내용 |
| --- | --- |
| Actions에 프로그램이 안 보임 | `.github/workflows/news.yml` 경로와 기본 브랜치에 저장했는지 확인 |
| `Run workflow`가 없음 | YAML 전체를 정확하게 복사했는지, 기본 브랜치에 `workflow_dispatch`가 있는지 확인 |
| `requirements.txt`가 없다는 오류 | 파일이 저장소 최상위에 있는지 확인. 상위 폴더나 ZIP만 올리면 안 됨 |
| Secrets 등록 안내 오류 | 표의 네 이름을 그대로 Repository secrets에 등록 |
| 텔레그램 401 또는 404 | 토큰과 주소를 확인하고 필요한 경우 토큰 재발급 |
| 텔레그램 400 또는 403 | 내 Chat ID 확인, 새 봇에 `/start` 전송, 봇 차단 해제 |
| 네이버 401 또는 403 | API HUB에서 발급한 Client ID/Secret인지, Application에 `뉴스`가 선택돼 있는지, 수정본 news_bot.py를 올렸는지 확인 |
| 다음 구조 변경·차단 오류 | 다음 수집 코드 점검 필요. 다른 포털의 정상 수집 기사는 계속 전송함 |
| 기록 저장 단계에서 403 | 9단계 쓰기 권한·브랜치 보호 설정 확인. 해결 전에는 중복 가능 |
| 실행 성공인데 새 기사가 안 옴 | 새로 발견한 기사가 없거나 제목·요약 조건에 맞지 않을 수 있음 |
| 정확히 10분마다 오지 않음 | GitHub 예약 실행 지연·누락 또는 포털 검색 반영 지연 가능 |
| 정기 실행이 멈춤 | Actions 비활성화 여부, 계정 사용량·결제 제한, 저장소 장기 미활동 확인 |

다음 수집 오류나 조회 상한 경고는 텔레그램에도 하루 한 번 알립니다. 텔레그램 자체가 막힌 경우에는 이 경고도 받을 수 없으므로 GitHub 실행 기록을 확인해야 합니다. 다음 페이지가 바뀌거나 GitHub 실행기 IP에서 접근이 제한되면 수집 코드를 수정해야 합니다. 접근 제한을 우회하는 기능은 없습니다.

**12. 간격 변경·중지**

- 기본은 10분입니다. GitHub에서 `.github/workflows/news.yml`을 열고 연필 버튼을 누르면 수정할 수 있습니다.
- 5분으로 바꾸려면 `cron: '*/10 * * * *'`을 `cron: '*/5 * * * *'`으로 바꿉니다.
- 30분으로 바꾸려면 `cron: '*/30 * * * *'`으로 바꿉니다. 기사 없음 문구와 중복 안내 간격은 코드에서 10분으로 설정되어 있으므로 간격을 바꿀 때 함께 수정해야 합니다.
- 변경 후 `Commit changes`로 저장합니다. 5분 미만 정기 실행은 GitHub Actions가 지원하지 않습니다.
- 중지: `Actions → Jeonbuk News Bot → 오른쪽 … → Disable workflow`.
- 재개: 같은 화면에서 `Enable workflow`. 오랫동안 중지했다면 아래 수집 범위 제한을 확인하세요.

**13. 알아두실 실제 동작 범위**

GitHub Actions는 정확한 시각의 실행을 보장하지 않습니다. 부하가 높으면 실행이 늦거나 누락될 수 있습니다. 공개 저장소에서 60일간 저장소 활동이 없으면 예약 실행이 비활성화될 수 있습니다. 한 달에 한 번 정도 Actions 상태를 확인하세요. 이 프로그램은 기사 기록이 바뀌면 커밋을 만들지만, 그것만으로 영구 실행을 보장한다고 가정하지는 않습니다. [GitHub 예약 실행 공식 설명](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

매 실행 때 최근 24시간을 겹쳐 확인해 늦게 검색에 잡힌 기사를 일부 보완합니다. 다만 검색어별 네이버 최대 1,000건, 다음 최대 약 100건까지만 조회합니다. 기사 급증·검색 누락·장시간 중단으로 이 범위를 벗어난 기사는 놓칠 수 있습니다. 상대 시간으로 표시된 다음 기사 시각은 근삿값이고, 날짜만 표시된 경우 한국시간 00:00으로 처리합니다. **모든 기사의 수집이나 업로드 즉시 알림을 보장하는 시스템은 아닙니다.**

전송 성공 응답을 받은 기사만 완료로 기록하고, 실패한 기사는 대기열에 남깁니다. 완료 기록은 30일 보관합니다. 다만 텔레그램이 메시지를 받은 직후 응답이 끊기거나, 기록을 GitHub에 저장하기 전에 실행기가 강제 종료되면 일부 중복이 생길 수 있습니다. 주소가 달라진 기사, 수정·재송고된 기사도 별도로 올 수 있습니다.

공개 저장소의 `data/state.json`에는 기사 링크·제목·요약·처리 기록이 포함될 수 있습니다. 봇 토큰, 채팅 ID, 네이버 인증키는 이 파일에 저장하지 않습니다. 검색 키워드 자체가 비공개 취재 계획이라면 비공개 저장소 사용을 고려하세요.

**14. 검증과 파일 설명**

다음의 실제 공개 검색 페이지에서 다섯 검색어와 페이지 이동을 확인했습니다. 테스트는 중복 처리, 첫 실행 제한, 전송 실패 후 재시작, 대기열 유지, 날짜 처리, 형식 변경 감지, 인증 URL을 로그에 노출하지 않는 오류 처리 등을 확인합니다.

본인의 네이버 인증키와 텔레그램 토큰을 입력하지 않은 상태이므로 **본인 계정으로의 네이버 실호출·텔레그램 실전송·GitHub 예약 실행은 아직 수행되지 않았습니다.** 10단계에서 직접 완료할 수 있습니다.

개발자가 점검할 때 쓰는 명령은 다음과 같습니다. 일반 사용자는 직접 실행할 필요가 없습니다.

```text
python -m pip install -r requirements.txt
python -m unittest -v
python news_bot.py
```

마지막 명령은 네 비밀값을 환경변수로 지정했을 때 실제 전송합니다. GitHub Actions에서는 이 작업을 설정 파일이 자동으로 수행합니다. 개발자 참고: [Daum 검색 공개 API 목록](https://developers.kakao.com/docs/latest/ko/daum-search/dev-guide)에는 뉴스 전용 검색 API가 없으므로 이 구현은 다음 뉴스 HTML에 의존합니다.
